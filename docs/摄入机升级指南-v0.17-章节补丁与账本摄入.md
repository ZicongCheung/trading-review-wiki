# 摄入机升级指南:v0.17 章节补丁 / 判断账本 / Embedding 路由

> 本文写给摄入机上的 Codex(以及维护 skills 的人)。目的:理解 v0.17 摄入系统的三个新能力、如何一次性完成环境准备、如何把日常摄入 skills 从旧参数切换到新参数、以及人审时新增了哪些检查点。
>
> 设计与决策背景见 [`提案-2026-07-07-时间线账本与供数架构-v6.md`](提案-2026-07-07-时间线账本与供数架构-v6.md)。

## 0. TL;DR

```sh
# 一次性准备(摄入机上执行)
git pull                                             # 更新本 CLI 仓库到 v0.17.0
security add-generic-password -U -s trading-wiki-openai-api -a api-key -w 'sk-...你的OpenAI key'
npm run codex:ingest -- embeddings build --project <wiki根>   # 全量建一次索引,之后自动增量

# 日常摄入:在原有 api-run 命令上加三个 flag
npm run codex:ingest -- api-run --provider codex \
  --source <raw文件> --project <wiki根> \
  --page-write-mode patch --judgments --embedding-routing
```

其余流程(`finalize` / `apply --write` / `batch-run` / dry-run 默认、写入边界)全部不变。不加这三个 flag 时行为与 v0.16.4 完全一致,可随时回退。

## 1. 三个新能力

### 1.1 `--page-write-mode patch`:章节补丁更新(提速主力)

- **update 页**不再让模型重写整页,而是输出章节补丁操作(JSON 数组):`replace_section` / `append_to_section` / `insert_section_after` / `update_frontmatter`。程序把补丁应用到旧页上,**未触及章节字节级原样保留**。
- **create 页和 source archive 仍是整页生成**(没有基底,补丁无意义)。
- 补丁 `content` 是**逐行字符串数组**(每个元素一行,空行用 `""`),不是内嵌 `\n` 的大字符串;解析层带控制字符自动修复。
- **每页独立回退**:补丁解析失败或锚点不存在时,该页自动回退整页生成,原因记入 `manifest.pagePatch.fallbacks`,不影响其他页。
- 审计产物:补丁原文存 `files/patch-*.md`,解析后的完整页仍存标准 FILE 产物,`finalize` 断点续跑兼容。
- 实测参考(2026-07-07,盘前纪要,30 页计划,4 路并发):全程 27 分钟,21/23 更新页走补丁,输出量约为整页重写的 1/4~1/5。

### 1.2 `--judgments`:判断账本(时间线知识库核心)

- 新账本 `data/facts/judgments.jsonl`,与 temporal facts 平行:**facts 记"世界发生了什么",judgments 记"当时怎么理解"**。
- Stage 2 规划时可输出 `judgmentWrites`,字段:
  - `kind`:`thesis`(判断)/ `expectation`(预期)/ `lesson`(教训)/ `stance`(仓位观点)
  - `status`:`held` / `revised` / `invalidated` / `expired`,新判断默认 `held`
  - `claim`(一句话原子判断)、`confidence`、`basedOnFacts`(关联 fact id)、`validAt`、`verifyBy`(验证窗口)、`visibility`
- **修正纪律**:新证据修正旧判断时,新增一条并在 `supersedes` 填旧 `jg_` id,永不改写旧行(与 facts 相同)。
- **可见性**:`stance` 默认 `visibility: personal`(不进公司快照);行业/主线/公司层面判断用 `team`。模型标错会产生软警告供人审。
- 写入边界:`judgmentWrites` 只允许写 `data/facts/judgments.jsonl`;确定性 id 去重,重复 apply 不重复追加;`apply` 端不需要 flag,永远认识 `judgmentWrites`。

### 1.3 `--embedding-routing`:语义路由(落页准度)

- 前置:`embeddings build` 建过索引(`.llm-wiki/embeddings/wiki-pages.json`,覆盖概念/股票/模式/错误/策略/人物页)。
- 摄入时对整源 + 每个 segment 做语义检索,把词法检索漏掉的相关页补进候选(标 `matchedBy: "embedding"`),已有候选加分。
- **降级安全**:索引缺失、key 缺失、API 报错都只降级为纯词法候选并留警告,绝不阻断摄入。路由摘要在 `candidate-pages.json` 的 `embeddingRouting` 字段。
- **索引自动维护**:`apply --write` 写入被索引目录的页面后自动增量刷新(report 的 `embeddingIndexRefresh` 字段);只有新增/改动页会重新嵌入,成本几乎为零。手工批量改页后可手动 `embeddings build` 补刷。
- Key 读取优先级:`--embedding-api-key` > 环境变量 `OPENAI_API_KEY` > Keychain `trading-wiki-openai-api` / `api-key`。

## 2. 行为变化(即使不加新 flag 也生效)

1. **存量 frontmatter 债降级**:update 页在改动前后**同样存在**的 fatal frontmatter 问题(如历史遗留 `confidence: 中低`)降级为 warning 并标 `preExisting: true`,不再拦整场 apply;**新引入**的非法值仍然 fatal。建议 Lint 时顺手清这些 preExisting 警告。
2. **manifest 新字段**:`pageWriteMode`、`pagePatch`(patched/full/fallbacks 统计)、`judgmentWrites`;apply report 新增 `plannedJudgmentWrites` / `duplicateJudgments` / `revisedJudgments` / `judgmentsWritten` / `judgmentIndex` / `embeddingIndexRefresh`。老字段全部保留。
3. **`wiki-change-review.md`** 增加三行:judgments planned / written / duplicate。
4. frontmatter 新增可选字段 `entity_key`、`visibility`(team/personal),不填不影响任何存量页;填错只给软警告。

## 3. skills 改造指引

- 找到调用 `npm run codex:ingest -- api-run ...` 或 `batch-run ...` 的 skill 脚本,在参数里追加:
  `--page-write-mode patch --judgments --embedding-routing`
- `batch-run` 三个 flag 同样支持,逐 source 透传。
- skill 的验收检查建议从原来的 `fatal == 0 / wroteRaw == false` 扩展为:
  - `pagePatch.fallbacks` 数量(偶发回退正常;持续大量回退说明补丁 prompt 或页面结构有问题)
  - `plannedJudgmentWrites` 数量与质量(claim 是否原子、是否有 verifyBy)
  - `embeddingRouting.status`(applied / skipped / failed)
  - preExisting 警告清单(供 Lint 排期)
- 人审重点新增:`files/patch-*.md`(补丁是否只动该动的章节)、dry-run report 里的 judgments 条目(stance 是否该 personal)。

## 4. 双机分工提醒

- **摄入机**(本指南对象):正常 `api-run -> finalize -> apply --write`,索引随 apply 自动增量刷新;写完 push。
- **检索/试用机**:`git pull` 拉到新页面后,索引不会自动刷新(没有本机 apply),pull 后跑一次 `embeddings build`(增量,秒级)。
- **不要把 embedding 索引提交进 git**:在 live wiki 的 `.gitignore` 加 `.llm-wiki/embeddings/`(72MB 且频繁变化);两台机器各自 build 一次即可。

## 5. 已知边界与后续

- 补丁模式对"章节结构混乱的旧页"(没有规范 `##` 章节)会更多回退到整页生成——正常,整固这些页是 Lint 的活。
- 单篇宽计划(如一篇纪要规划 30 页)目前只记录计数,默认软预算告警是下一批改进(见提案 §5 步骤路线)。
- 时间线自动区块(`## 时间线` 从 facts+judgments 渲染进页面)与 `ask --as-of` 回放、公司快照导出管道尚未实装,账本先积累数据。
