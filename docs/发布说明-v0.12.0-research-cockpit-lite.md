# v0.12.0 Research Cockpit Lite 发布说明

发布日期：2026-06-19

## 一句话

`v0.12.0` 把 Trading Review Wiki 从“功能很多的研究控制台”，收敛成基金经理每天可用的“舆情驱动假设待办系统”：

```text
AI 并发找假设 / 手工建假设
-> 假设跟踪表
-> 选择微信聊天文档
-> 扫描新增舆情
-> 生成待处理卡片
-> 人工确认 / Ask 深挖 / 忽略
-> 状态和来源沉淀为假设记忆
```

## 核心变化

### 1. Research Cockpit Lite 默认首页

默认首页只回答一个问题：

> 今天有什么新信号，会不会改变我正在跟踪的假设？

首屏主动作收敛为：

- `AI 并发找假设`
- `扫描微信新增`
- `自动跟踪`
- `刷新`

自训练、proposal、autoresearch、实验账本、补证细节默认折叠到高级区，不再干扰日常投研判断。

### 2. 微信聊天文档作为增量信号源

系统优先选择：

```text
raw/微信聊天/YYYY-MM-DD.md
```

如果当天文件不存在，会使用最近修改文件并提示。扫描流程为：

```text
读取选中文档
-> 导入新增
-> 去重
-> 规则路由
-> 可选 LLM 复核
-> 生成待处理卡片
```

自动扫描只允许写：

```text
.llm-wiki/wechat-inbox/**
```

不会写 `wiki/**`，不会改 `raw/**`，不会触发真实交易。

### 3. 待处理卡片替代工程日志

每张卡片必须回答：

- 这是什么信号：`新催化 / 二次确认 / 市场反馈 / 硬证据 / 反证 / 叙事扩散`
- 影响哪条假设
- 建议状态是否变化
- 为什么
- 下一步是 `确认`、`Ask 深挖` 还是 `忽略`

系统会过滤日期、编号、弱标题、泛词和同源重复信号，减少 `2026-06-19`、`3.` 这类垃圾候选。

### 4. Ask 深挖成为假设研究按钮

`Ask 深挖` 复用现有 `ask --agentic` 能力，并针对单条假设自动构造问题。输出重点是：

- 关联股票
- 最直接受益
- 利好排序
- 当前阶段
- 最大缺口
- 一句话结论
- 原 ask 六段全文和来源

本版修复了此前 `hypothesis ask` 只返回检索 context、没有真正生成 agentic answer 的问题。

### 5. 状态更新必须人工确认

扫描和 LLM 复核只生成建议，不直接改假设。

只有点击确认或运行：

```sh
npm run codex:ingest -- hypothesis status-update --id <hypothesis-id> --status strengthening --reason "..." --write
```

才会写入：

```text
.llm-wiki/hypotheses/**
.llm-wiki/hypothesis-events/**
.llm-wiki/hypothesis-alerts/**
```

### 6. 高级实验室保留完整递归闭环入口

首页默认降噪，但本版没有删除复杂能力，而是收进 `高级实验室`。它面向“需要把一个信号继续推进成可复盘实验”的场景，包含：

- `闭环状态`：读取 self-question、autoresearch ledger、self-train next 等状态，判断递归研究链路卡在哪一步。
- `dry-run 闭环`：串联自提问、验证、归因、证据缺口、策略建议、自训练计划和样本导出预演，不直接写正式库。
- `策略建议 dry-run / 写入 proposal`：从实验账本生成待审核策略改进建议，只写 `.llm-wiki/policy-proposals/**`。
- `自训练计划 dry-run / 写入训练计划`：把待审动作转成非执行型训练计划，只写 `.llm-wiki/self-training-plans/**`。
- `补证对话 / 数据源搜集`：把用户粘贴的路演、表格、公告、调研纪要或 API 搜集指令交给 LLM 整理成补证草稿，再交给 Watchtower 扫描假设。
- `微信增量观察`：保留 raw 微信聊天 fallback 的导入、去重、processed 统计和 dry-run events/alerts 观察。
- `阶段进度 / 阶段输出`：显示每一步运行结果，用于排查按钮是否真的跑通，而不是 token 级刷屏。
- `假设状态列表 / alerts / 候选新假设 / 策略改进建议 / 自训练待审动作 / 实验账本 / 证据缺口`：保留工程审计视图，供复盘、调试和后续自训练读取。

高级实验室的定位不是日常盯盘主界面，而是“把一个值得追的假设推进到实验、补证、proposal、自训练样本”的工作区。

## 新增命令和脚本

```sh
npm run codex:ingest -- hypothesis watch --sources wechat_incremental --since 30m --llm-review auto
npm run codex:ingest -- hypothesis status-update --id <hypothesis-id> --status strengthening --reason "..." --write
npm run codex:ingest -- hypothesis ask --id <hypothesis-id> --agent-concurrency 3 --agent-timeout-ms 300000
npm run codex:ingest -- hypothesis supplement-draft --body "..." --selected-sources ima,cninfo,qichacha,tushare
npm run codex:ingest -- hypothesis supplement --title "..." --body "..." --hypothesis-id <id> --write
npm run codex:ingest -- self-question loop --stages generate,validate,attribute,evidence,policy,self-train,self-train-plan,export
npm run codex:ingest -- autoresearch policy propose --write
npm run codex:ingest -- self-train plan --write
npm run sag:sync
npm run machine:preflight
npm run machine:snapshot
```

## 安全边界

- 不自动交易。
- 不自动写正式 `wiki/**`。
- 不自动改 `raw/**`。
- 不自动应用 prompt、segment 配置或策略。
- 微信自动扫描只写 `.llm-wiki/wechat-inbox/**`。
- 假设状态更新必须人工确认。
- Tauri 只允许固定 action，不允许任意 shell。
- 外部文本按不可信输入处理，输出继续脱敏。
