# 专业插件能力层集成说明

这三个插件不是新的数据源，而是 Trading Review Wiki 主程序之上的专业能力层。主程序仍负责证据抓取、CLI 编排、审计产物、写入边界和训练样本；插件负责在合适场景下提供更专业的分析框架、质控框架和交付格式。

## 1. 总体分工

| 层级 | 主体 | 职责 | 典型产物 |
|---|---|---|---|
| 数据源层 | CNINFO / Tushare / QCC / Tavily / wiki / raw / SQL / Excel | 提供公告、财报、招投标、行情、产业底表和知识库证据 | `raw/**`、`wiki/**`、`data/facts/**`、SQL 查询结果、Excel |
| 结构化处理层 | Data Analytics | 数据质量检查、指标诊断、横向对比、可视化、报告和 dashboard | 数据质控记录、分析报告、图表、dashboard、notebook |
| 买方股票研究层 | Public Equity Investing | 上市公司投资 thesis、催化剂、估值、仓位风险和退出条件 | tearsheet、投资 memo、DCF/comps、thesis tracker |
| 特殊交易事项层 | Investment Banking | 并购、重组、定增、债务融资、交易条款和模型审计 | CIM/teaser、交易模型、accretion/dilution、融资或重组 memo |
| 主程序落地产物 | `codex:ingest` CLI | 证据组织、审计、写入边界、递归实验账本和训练样本 | `.llm-wiki/**`、`deep-company-report.md`、`financial-model-v2.xlsx`、`evidence-ledger.json` |

默认顺序已经升级为“混合插件优先”：

```text
主程序抓数据、证据包、底表、模型模板和写入边界
-> Data Analytics 先做表格、口径、单位、tie-out、公式重算风险
-> Public Equity Investing 作为主分析师直接生成公司深度报告
-> Investment Banking 只在并购/重组/融资/交易结构出现时介入
-> 主程序生成 publish-readiness 和 wiki-change-candidates
```

## 2. 公司深研 V2：`--plugin-led`

推荐入口：

```sh
npm run codex:ingest -- company-research \
  --stock <code|name> \
  --deep \
  --plugin-led
```

`--plugin-led` 的设计不是“主程序先写一篇深度稿，再让插件评审”，而是：

```text
主程序 evidence pack / financials / document extract / business breakdown / model template
-> Data Analytics 模型与证据质控
-> Public Equity Investing 主报告
-> Investment Banking 可选交易事项分析
-> 主程序发布门禁和 wiki 候选稿
```

主要产物：

| 产物 | 作用 |
|---|---|
| `evidence-pack.json` | 插件可读的证据包 |
| `financials.json` | 财务底表 |
| `document-extract.json` | 公告和文档抽取结果 |
| `business-breakdown.json` | 业务、分部、产能、资本开支、交易事项拆解 |
| `financial-model-v2-template.json` / `financial-model-v2.json` / `financial-model-v2.xlsx` | 模型框架和可审计底表 |
| `plugin-led/plugin-led-input.json` | 插件主导链路输入包 |
| `plugin-led/data-analytics-model-analysis.md` | Data Analytics 模型、口径和证据质控 |
| `plugin-led/plugin-led-company-report.md` | Public Equity Investing 分段拼接后的主分析草稿 |
| `plugin-led/plugin-led-company-report-complete.md` | 完整性修复触发后的最终主报告，仅在需要时生成 |
| `plugin-led/investment-banking-transaction-analysis.md` | 仅在交易事项触发或强制参数下生成 |
| `plugin-led/investment-banking-skipped.md` | 无交易事项时的跳过说明 |
| `plugin-led/report-completeness.json` | 主报告章节、行数、表格数完整性校验 |
| `plugin-led/publish-readiness.json` | 发布门禁 |
| `plugin-led/plugin-led.json` | `--plugin-led` 汇总清单，最终主报告路径以 `outputs.pluginLedReport` 为准 |
| `deep-company-report.md` | 兼容旧 reviewer/skill 的主报告副本 |
| `wiki-change-candidates.md` | 候选 wiki 写入稿，不自动发布 |
| `run-summary.json` | 记录 `pluginLed` 状态、耗时、输出路径、IB 是否触发、门禁结果 |

回退和对照：

- `--plugin-review` / `--plugin-optimize` 保留，用于旧链路对照。
- company deep research skill 默认走 `--plugin-led`。
- 设置 `PLUGIN_LED=0` 可回到旧 review/optimize 链路。
- `--force-investment-banking-review` 只在明确需要 IB 参与时使用。

写入边界：

- 插件只读主程序产物。
- 插件不管理 CNINFO/Tushare/SQL/QCC 凭证。
- 插件不直接写正式 `wiki/**`。
- 输出只写 `.llm-wiki/company-research/**`。
- 正式 wiki 写入仍走候选稿审核或现有 apply 流程。

## 3. Data Analytics

定位：分析工程师 + 数据质控 + 报告仪表盘。

适合调用：

- 检查 `financial-model-v2.xlsx` 的公式、口径、缺失值、异常值和一致性。
- 检查年报抽表、公告抽表、Excel 产业底表是否粒度一致。
- 做公司横向对比，例如 MLCC、算力租赁、存储、光模块、PCB、SiC。
- 做检索质量评估：召回率、证据覆盖率、raw 噪声率、结构字段命中率。
- 做研究质量 dashboard：问题数、验证数、证伪数、证据缺口、样本质量门。
- 做 TAM/SAM/SOM、敏感性测算和驱动因素拆解。
- 在 `--plugin-led` 中优先接管公司深研的模型、表格、单位、tie-out、公式重算风险和证据覆盖。

输入：

- 主程序导出的 SQL 结果、CSV、Excel、JSON、JSONL。
- `.llm-wiki/company-research/**` 下的模型和 evidence ledger。
- `.llm-wiki/agent-runs/**`、`.llm-wiki/experiments/**`、`.llm-wiki/exports/**`。
- `raw/产业数据/**` 这类原始产业底表。

边界：

- 它不是 Wind、FactSet、Choice 或行情数据供应商。
- 高置信结论仍必须回到 CNINFO、Tushare、QCC、SQL、wiki/raw/facts 等证据层。
- 当前 Data Analytics 插件尚未做项目级 onboarding；正式做分析时要显式提供数据文件、SQL 结果或导出目录。

## 4. Public Equity Investing

定位：买方研究员 / PM 助手。

适合调用：

- 明确股票、ticker、上市公司或持仓的问题。
- 财报 preview / deep dive。
- long/short pitch、投资 memo、tearsheet。
- 可比公司估值、DCF、三表模型、模型更新。
- 催化剂日历、预期差、证伪信号、仓位和风险管理。
- thesis tracker：为什么买、为什么不买、什么时候退出。

和主程序的连接：

- 在 `--plugin-led` 中作为主分析师，不等待旧版主程序深稿后再评审。
- 输入 `plugin-led/plugin-led-input.json`、`evidence-pack.json`、`financial-model-v2.xlsx` 和 Data Analytics 输出。
- 输出 `plugin-led/plugin-led-company-report.md`，并同步为兼容文件 `deep-company-report.md`。
- 把结论拆回系统语言：已验证事实、弹性假设、催化剂、证伪信号、交易含义、退出条件。

边界：

- 普通资料整理、知识库摄入、泛行业研究不默认调用它。
- A 股数据仍靠 CNINFO、Tushare、QCC、本地 SQL、wiki/raw。
- 插件负责研究框架，不负责替代主程序的证据抓取和审计账本。

触发规则：

- 用户明确 `@public-equity-investing` 或点名 Public Equity Investing。
- 或问题明显是上市股票投资研究，例如买方 thesis、估值、催化剂、仓位、加减仓或退出决策。

## 5. Investment Banking

定位：投行交易执行工具箱。

适合调用：

- 并购、重组、资产注入、定增、可转债、债务融资、资本市场发行。
- 重大事项公告里的交易条款、对价、业绩承诺、估值、股权稀释。
- M&A merger model、accretion/dilution、DCF、trading comps、LBO。
- CIM、teaser、pitch deck、投资人/买方名单、交易流程管理。
- 对 `financial-model-v2.xlsx` 做更严格的模型 tie-out 和交易事项审计。

和主程序的连接：

- 当 `company-research --deep --plugin-led` 或 CNINFO 公告识别出并购/融资/重组事件时，把事件包交给 Investment Banking 做交易结构分析。
- 分析结果仍回写为 `.llm-wiki/company-research/**` 候选产物或人工审阅材料，不直接写正式 `wiki/`。

边界：

- 日常股票研究不用它，优先用 Public Equity Investing。
- 没有交易结构时，不把普通估值问题强行写成投行材料。
- 不作为自动交易或自动写 wiki 的权限来源。

触发规则：

- 用户明确 `@investment-banking` 或点名 Investment Banking。
- 或问题明显是投行执行场景，例如 CIM、并购模型、融资方案、重组、发行、债务或交易条款。

## 6. 进入递归闭环的位置

这三个能力层进入递归自训练系统时，只能作为被审计的辅助证据和专业评审，不直接自动改系统。

```text
self-question
-> ask --agentic
-> market validation / company-research / data-source
-> company-research --deep --plugin-led
-> Data Analytics 模型和证据质控
-> Public Equity Investing 主报告
-> Investment Banking 特殊交易事项分析
-> attribution
-> experiment score
-> policy proposal
-> 人工审核
```

Phase 边界：

- Phase 5A：插件只能生成分析、审计和待审核建议。
- Phase 6：人工批准后，可把低风险配置改动纳入 patch candidate。
- Phase 7：多次验证后，只允许白名单低风险配置自动应用。
- Phase 8：插件分析可以进入模拟交易评估，但不能替代交易验证。
- Phase 9：插件分析只能支持受控真实交易建议，不直接下单。

## 7. 最小可用工作流

公司深研后复核：

```text
company-research --deep --plugin-led
-> Data Analytics 检查模型/表格/证据覆盖
-> Public Equity Investing 生成主报告、买方 thesis 和退出条件
-> 如有并购/融资/重组，再交给 Investment Banking
-> 结果进入 self-question attribution / experiment ledger / policy proposal
```

产业主题后复核：

```text
ask --agentic 深度主题问题
-> segment market validation
-> Data Analytics 做横向对比和图表
-> Public Equity Investing 只对明确股票池做买方结论
-> attribution 记录 confirmed/divergent/disconfirmed/insufficient
```

交易事项后复核：

```text
CNINFO 重大事项公告
-> company-research --deep --plugin-led 生成事件包
-> Investment Banking 拆条款/对价/稀释/业绩承诺
-> Public Equity Investing 判断对股票 thesis 的影响
-> Data Analytics 检查模型和敏感性
```

## 8. 使用口令

常用调用方式：

```text
@data-analytics 检查这次 plugin-led 的 financial-model-v2.xlsx、evidence-pack.json 和 business-breakdown.json，找公式、口径、缺口和异常值。
@public-equity-investing 基于 plugin-led-input.json 和 data-analytics-model-analysis.md，直接生成公司主报告、买方 thesis、催化剂、证伪信号和退出条件。
@investment-banking 基于这份重大资产重组公告和 plugin-led-input.json，拆交易条款、估值、稀释、业绩承诺和对股价 thesis 的影响。
```

核心原则：

- 主程序负责证据。
- 插件负责专业框架。
- 审计账本负责复盘。
- 人工审核负责进入系统更新。
