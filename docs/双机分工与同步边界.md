# 双机分工与同步边界

这份文档定义新 Mac Pro 和旧 Mac 的职责分工。核心原则是：旧机器是生产写入端，新机器是研究和开发端。两台机器可以共享证据，但不能同时写同一个 live wiki。

## 机器角色

| 机器 | 角色 | 主要工作 |
|---|---|---|
| 新 Mac Pro 128G | research/dev | 训练、检索索引、公司深研草稿、代码开发、测试、构建、推送 |
| 旧 Mac | prod/automation | LaunchAgent、Gangtise、WeChat Radar、IMA watcher、daily-loop、摄入、备份和下游同步 |

## Source Of Truth

`/path/to/your-trading-wiki` 的主写入端是旧 Mac。新 Mac 使用旧 Mac 产出的快照进行训练、检索和实验。

旧 Mac 可以写：

- `/path/to/your-trading-wiki/raw/**`
- `/path/to/your-trading-wiki/wiki/**`
- `/path/to/your-trading-wiki/data/brain/**`
- `/path/to/your-trading-wiki/data/facts/**`
- `/path/to/your-trading-wiki/.llm-wiki/daily-research/**`
- `/path/to/your-trading-wiki/.llm-wiki/wiki-feedback/**`

新 Mac 默认只写：

- 代码仓库和 feature branches
- `/path/to/your-trading-wiki-snapshots/**`
- `/path/to/your-trading-wiki-research/**`
- `/path/to/trading-indexes/**`
- `/path/to/training-runs/**`

新 Mac 可以生成 `.llm-wiki/company-research/**`、索引、训练样本和评测结果，但这些产物应该先作为研究包审核，再由旧 Mac 或明确的一次性流程写入正式 wiki。

## 代码流

1. 新 Mac 改代码、跑测试、构建。
2. 新 Mac commit 并 push。
3. 旧 Mac 在自动化停稳后执行 `git pull --ff-only`。
4. 旧 Mac 运行自动化 preflight。
5. 旧 Mac 重启或继续对应 LaunchAgent。

旧 Mac 不直接开发代码，除非是紧急修复。紧急修复也要尽快推回远端，让新 Mac 同步。

## 快照流

旧 Mac 继续产出 live corpus。新 Mac 定期拉取只读研究快照：

```sh
npm run machine:snapshot -- \
  --source /path/to/your-trading-wiki \
  --dest-root /path/to/your-trading-wiki-snapshots
```

默认会生成带北京时间戳的目录，并维护 `latest` symlink。新 Mac 上的检索和训练优先指向：

```text
/path/to/your-trading-wiki-snapshots/latest
```

例如：

```sh
npm run codex:ingest -- ask \
  --query "最近机器人产业链有哪些兑现和反证？" \
  --project /path/to/your-trading-wiki-snapshots/latest \
  --provider codex \
  --show-sources
```

## 自动化启动前检查

旧 Mac 的自动化入口前应先跑：

```sh
npm run machine:preflight -- \
  --role prod \
  --repo /path/to/trading-review-wiki \
  --project /path/to/your-trading-wiki \
  --require-branch main
```

检查通过后再执行具体自动化。检查失败时不要继续摄入或写 wiki。

开发中的新 Mac 可以跑：

```sh
npm run machine:preflight -- \
  --role research \
  --repo /path/to/trading-review-wiki \
  --project /path/to/your-trading-wiki-snapshots/latest \
  --allow-dirty
```

## 禁止事项

- 不要让新旧两台机器同时对同一个 `/path/to/your-trading-wiki` 写入。
- 不要用 iCloud/网盘双向同步 live wiki 目录。
- 不要在新 Mac 的训练任务里对旧 Mac live corpus 跑 `apply --write`。
- 不要在旧 Mac 自动化运行中直接切分支或改未测试代码。
- 不要把数据库密码、token 或连接串写入 Markdown 或 commit。

## 故障处理

如果发现两台机器都写过 live corpus：

1. 立刻停止新 Mac 上所有会写入 `raw/`、`wiki/`、`data/` 的任务。
2. 在旧 Mac 执行 `git status --short`，确认正式知识库差异。
3. 只保留有证据链的写入，撤回实验缓存和重复产物。
4. 重新从旧 Mac 生成快照给新 Mac。

如果自动化 preflight 失败：

1. 先看失败项，不要继续跑摄入。
2. dirty code repo 先 commit、stash 或回到稳定 commit。
3. live project 不可写时先修复目录权限。
4. secret scan 命中时只处理文件路径，不打印 secret 内容。
